

### 📖 核心原理解析

投机解码的目标很明确：把自回归生成从“一次一步”变成“一次一串”。它将每一步拆解为两个阶段：



1. **草稿生成 (Draft)**：使用一个轻量级的**草稿模型**，快速生成 `K` 个候选Token（`K` 通常设为5\~6）。

2. **并行验证 (Verify)**：**目标模型**一次性处理这 `K` 个候选Token，并**并行地**判断每个位置是否应该接受草稿模型的预测。

这个流程中有两个核心概念：



* **草稿模型 (Draft Model)**：通常是与目标模型同系列的小参数量版本（例如，用Llama-3.2-1B给Llama-3.1-70B打草稿）。它们必须共享同一个分词器(Tokenizer)。

* **接受率 (Acceptance Rate, α)**：这是决定加速效果的关键。它表示草稿模型提出的Token被目标模型接受的比例。α 越高，加速效果越好。接受率受任务类型影响很大：**代码生成或数学推理等确定性强的任务，接受率可达70%-85%**；而创意写作等随机性强的任务，接受率则低得多。

### 💻 从零构建核心流程

下面，我们抛开现成的框架，用一个完整的Python脚本模拟最核心的“草稿-验证-接受”逻辑。这个脚本可以在本地运行，用于观察整个流程的演进。



```python
import torch
import torch.nn.functional as F

# ==================== 1. 设置参数 ====================
torch.manual_seed(42)  # 固定随机种子，保证结果可复现
K = 5                 # 草稿步长，即草稿模型一次生成几个候选Token

# 模拟词汇表大小和模型的输出logits
VOCAB_SIZE = 10       # 用一个小词汇表便于观察
# ==================== 2. 模拟草稿模型和目标模型的输出 ====================
def target_model_forward(tokens):
    """模拟目标模型根据给定Token序列，计算下一个Token的概率分布"""
    # 在实际场景中，这是大模型的一次前向传播
    # 这里，我们根据输入的最后一个Token，构造一个确定性分布方便演示
    if tokens[-1] == 1:
        # 如果最后一个Token是1，则下一个Token最可能是2
        logits = torch.tensor([-10.0, -10.0, 5.0, 2.0, 0.0, -10.0, -10.0, -10.0, -10.0, -10.0])
    else:
        # 其他情况，最可能是3
        logits = torch.tensor([-10.0, -10.0, -10.0, 5.0, 2.0, -10.0, -10.0, -10.0, -10.0, -10.0])
    return F.softmax(logits, dim=-1)

def draft_model_forward(tokens):
    """模拟草稿模型根据给定Token序列，计算下一个Token的概率分布"""
    # 实际中，这是一个小模型。这里我们模拟它有时会“猜错”
    if tokens[-1] == 1:
        # 草稿模型也认为下一个是2，但概率没那么高（模拟不确定性）
        logits = torch.tensor([-10.0, -10.0, 3.0, 1.0, 0.0, -10.0, -10.0, -10.0, -10.0, -10.0])
    else:
        # 在tokens[-1] != 1时，草稿模型“猜错”，认为下一个是4，但实际是3
        logits = torch.tensor([-10.0, -10.0, -10.0, 1.0, 3.0, -10.0, -10.0, -10.0, -10.0, -10.0])
    return F.softmax(logits, dim=-1)

# ==================== 3. 投机解码的核心循环 ====================
def speculative_decoding_loop(prompt_ids, max_new_tokens=20):
    # 初始化生成的Token序列
    generated_ids = prompt_ids.copy()
    print(f"Prompt: {prompt_ids}")
    
    total_draft_tokens = 0
    total_accepted_tokens = 0

    while len(generated_ids) < max_new_tokens:
        # -------- 阶段1: 草稿生成 (Drafting) --------
        draft_tokens = []
        # 临时序列，用于草稿模型一步步生成K个Token
        draft_context = generated_ids.copy() 
        
        print(f"\n--- 当前已生成: {generated_ids[-3:]} (len={len(generated_ids)}) ---")
        for _ in range(K):
            # 1. 草稿模型推理一步，得到概率分布
            draft_probs = draft_model_forward(draft_context)
            # 2. 采样得到下一个Token (贪心采样，取概率最高的)
            next_draft_token = torch.argmax(draft_probs).item()
            draft_tokens.append(next_draft_token)
            # 3. 将新Token追加到草稿上下文中，继续生成下一个草稿
            draft_context.append(next_draft_token)
        
        print(f"草稿模型提出的 {K} 个候选Token: {draft_tokens}")

        # -------- 阶段2: 并行验证 (Verification) --------
        # 关键：构建验证序列 [generated_ids + draft_tokens]
        verify_context = generated_ids + draft_tokens
        
        # 目标模型并行计算验证序列中每个位置（除最后一个）的下一个Token分布
        target_probs_list = []
        for i in range(len(verify_context) - 1):
            # 对验证序列的每个位置，用目标模型预测下一个Token
            probs = target_model_forward(verify_context[:i+1])
            target_probs_list.append(probs)

        # -------- 阶段3: 接受与拒绝 (Accept/Reject) --------
        accepted_count = 0
        for i, draft_token in enumerate(draft_tokens):
            # 获取目标模型在第i个位置给出的概率分布
            target_probs = target_probs_list[i]
            # 贪心策略：如果草稿Token等于目标模型概率最高的Token，则接受
            target_best_token = torch.argmax(target_probs).item()
            if draft_token == target_best_token:
                accepted_count += 1
            else:
                # 一旦遇到第一个分歧点，立即停止接受，并回退到目标模型的预测
                print(f"  在位置 {i} 出现分歧: 草稿Token={draft_token}, 目标最佳Token={target_best_token}")
                break

        # -------- 更新生成的Token序列 --------
        # 1. 接受所有通过的草稿Token
        accepted_tokens = draft_tokens[:accepted_count]
        generated_ids.extend(accepted_tokens)
        
        # 2. 如果草稿没有被全部接受(accepted_count < K)，则补充一个来自目标模型的Token
        if accepted_count < K:
            # 获取分歧位置的目标模型最佳Token
            fallback_token = torch.argmax(target_probs_list[accepted_count]).item()
            generated_ids.append(fallback_token)
            print(f"  回退并追加: {fallback_token}")
        else:
            # 如果全部接受，还需要再生成一个Token来“收尾”，否则会丢失一步信息
            # 获取最后一个位置的目标模型最佳Token
            final_probs = target_model_forward(generated_ids)
            final_token = torch.argmax(final_probs).item()
            generated_ids.append(final_token)
            print(f"  全部接受！收尾追加: {final_token}")

        # 更新统计信息
        total_draft_tokens += K
        total_accepted_tokens += accepted_count

    # 打印统计信息
    print("\n" + "="*30)
    print(f"本次生成共使用了 {len(generated_ids)} 个Token")
    print(f"草稿阶段共提出 {total_draft_tokens} 个候选Token")
    print(f"共接受了 {total_accepted_tokens} 个Token (接受率: {total_accepted_tokens/total_draft_tokens:.2%})")
    print(f"最终生成的Token序列: {generated_ids}")
    return generated_ids

# ==================== 4. 运行实验 ====================
if __name__ == "__main__":
    # 用一个简单的Prompt开始
    # 我们的模拟环境中，Token 1 和 2 可以生成连续的序列
    prompt = [1, 1]
    speculative_decoding_loop(prompt, max_new_tokens=20)
```



### 📊 结果分析与理解

运行上述代码，你会看到一次投机解码循环的清晰演进过程。它完美展示了核心理论：



1. **从串行到并行**：草稿模型先用 `K` 步生成了 `K` 个Token，而验证阶段则**一次性地**对这些Token进行了评判。这揭示了投机解码加速的根本——用一次大模型前向传播的成本，去验证多个草稿Token。

2. **接受率是加速的关键**：在代码的统计输出中，你会看到类似“草稿阶段共提出X个候选Token，共接受了Y个Token”的信息，`Y/X` 即是接受率。这个比率直接决定了实际能节省多少步大模型推理。

3) **数学上的无损保证**：注意逻辑细节——遇到第一个分歧点时，程序会“回退并追加”一个来自目标模型的Token，并丢弃后续所有草稿。这个机制保证了最终输出的Token序列**完全等同于**每步都直接运行目标模型，实现了数学上的“无损加速”。
