### 一、整体架构概览

PD分离系统由三个核心组件构成：



```plain&#x20;text
┌─────────────────────────────────────────────────────────────┐
│                     用户请求                                 │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│              Router（路由层）                                │
│     - 将请求路由到Prefill实例                               │
│     - 协调P→D的KV传输                                      │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌───────────────────┐              ┌───────────────────┐
│  P实例 (Prefill)   │  ── KV传输 ──▶│  D实例 (Decode)   │
│  计算密集型         │  (NCCL/RDMA) │  访存密集型         │
│  GPU 0             │              │  GPU 1             │
│  生成KV Cache      │              │  消费KV生成Token    │
└───────────────────┘              └───────────────────┘
```



KV Cache传输是PD分离的“生命线”，vLLM支持多种Connector：



| Connector             | 特点                            | 适用场景              |
| --------------------- | ----------------------------- | ----------------- |
| **PyNcclConnector**   | 基于PyNCCL的P2P通信                | 单机多卡/多机NVIDIA集群   |
| **P2pNcclConnector**  | 底层NCCL P2P传输                  | 低延迟要求             |
| **NixlConnector**     | NVIDIA Inference Xfer Library | 多机RDMA/InfiniBand |
| **LMCacheConnector**  | 通过LMCache服务器中转                | 需要KV缓存持久化         |
| **MooncakeConnector** | Mooncake分布式KV存储               | 大规模集群部署           |





### 二、方案一：离线推理模式（单机双卡）

这是vLLM官方示例中的标准实现。我们在两个独立的Python进程中分别启动Prefill节点和Decode节点，通过`P2pNcclConnector`传输KV Cache。



#### 2.1 完整源代码

```python
#!/usr/bin/env python3
"""
vLLM PD分离 - 离线推理示例
功能：在GPU 0上运行Prefill，在GPU 1上运行Decode，通过NCCL传输KV Cache
参考：vLLM官方 examples/offline_inference/disaggregated_prefill.py
"""

import os
import time
from multiprocessing import Event, Process

from vllm import LLM, SamplingParams
from vllm.config import KVTransferConfig


def run_prefill(prefill_done: Event):
    """
    Prefill节点 (生产者)
    在GPU 0上运行，处理Prompt生成KV Cache并发送给Decode节点
    """
    # 指定使用GPU 0
    os.environ["CUDA_VISIBLE_DEVICES"] = "0"
    
    # 准备Prompts
    prompts = [
        "Hello, my name is",
        "Hi, your name is",
        "Tell me a very long story",
    ]
    
    # 采样参数：只生成1个Token（仅用于触发Prefill）
    sampling_params = SamplingParams(
        temperature=0,
        top_p=0.95,
        max_tokens=1  # Prefill节点只生成1个Token，主要目的是产生KV Cache
    )
    
    # 配置KV传输：使用P2pNcclConnector
    # kv_rank=0 表示这是第0个节点（Prefill），kv_parallel_size=2 表示共2个节点
    ktc = KVTransferConfig(
        kv_connector="P2pNcclConnector",
        kv_role="kv_producer",   # 生产者角色
        kv_rank=0,               # 节点编号
        kv_parallel_size=2,      # 总节点数（1个P + 1个D）
    )
    
    # 初始化LLM引擎
    llm = LLM(
        model="meta-llama/Meta-Llama-3.1-8B-Instruct",
        kv_transfer_config=ktc,
        max_model_len=2000,
        gpu_memory_utilization=0.8,  # A6000 40GB显存用0.8
    )
    
    # 执行Prefill，生成的KV Cache会自动通过NCCL发送给Decode节点
    llm.generate(prompts, sampling_params)
    print("✅ Prefill节点完成，KV Cache已发送")
    
    # 标记Prefill完成
    prefill_done.set()
    
    # 保持进程运行，等待Decode节点完成
    try:
        while True:
            time.sleep(1)
    except KeyboardInterrupt:
        print("Prefill节点被用户停止")


def run_decode(prefill_done: Event):
    """
    Decode节点 (消费者)
    在GPU 1上运行，接收KV Cache并继续生成Token
    """
    # 指定使用GPU 1
    os.environ["CUDA_VISIBLE_DEVICES"] = "1"
    
    # 与Prefill节点相同的Prompts（用于匹配KV Cache）
    prompts = [
        "Hello, my name is",
        "Hi, your name is",
        "Tell me a very long story",
    ]
    
    # 采样参数：这次生成完整的回复
    sampling_params = SamplingParams(
        temperature=0,
        top_p=0.95,
        max_tokens=50,  # Decode节点生成50个Token
    )
    
    # 配置KV传输：消费者角色
    ktc = KVTransferConfig(
        kv_connector="P2pNcclConnector",
        kv_role="kv_consumer",   # 消费者角色
        kv_rank=1,               # 节点编号（第1个）
        kv_parallel_size=2,      # 总节点数
    )
    
    # 等待Prefill节点完成KV Cache的发送
    print("⏳ 等待Prefill节点完成...")
    prefill_done.wait()
    print("✅ Prefill节点已完成，开始Decode")
    
    # 初始化LLM引擎（会从Prefill节点接收KV Cache）
    llm = LLM(
        model="meta-llama/Meta-Llama-3.1-8B-Instruct",
        kv_transfer_config=ktc,
        max_model_len=2000,
        gpu_memory_utilization=0.8,
    )
    
    # 执行Decode：KV Cache已就绪，直接生成Token
    outputs = llm.generate(prompts, sampling_params)
    
    # 打印结果
    for i, output in enumerate(outputs):
        print(f"\n📝 Prompt {i+1}: {prompts[i]}")
        print(f"   Generated: {output.outputs[0].text}")
    
    print("\n✅ Decode节点完成")


def main():
    """主函数：启动Prefill和Decode两个进程"""
    print("=" * 60)
    print("🚀 vLLM PD分离 - 离线推理示例")
    print("   Prefill → GPU 0 (计算密集型)")
    print("   Decode  → GPU 1 (访存密集型)")
    print("=" * 60)
    
    # 创建事件用于进程间同步
    prefill_done = Event()
    
    # 启动Prefill进程
    p_prefill = Process(target=run_prefill, args=(prefill_done,))
    p_prefill.start()
    
    # 稍等一下让Prefill先启动
    time.sleep(2)
    
    # 启动Decode进程
    p_decode = Process(target=run_decode, args=(prefill_done,))
    p_decode.start()
    
    # 等待两个进程完成
    p_prefill.join()
    p_decode.join()
    
    print("\n🎉 PD分离推理完成！")


if __name__ == "__main__":
    main()
```

| `kv_parallel_size` | 总节点数 | `2`                  | `2`                  |

#### 2.3 关键设计要点

1. `max_tokens=1`**的妙用**：Prefill节点的`max_tokens=1`意味着它只生成1个Token就停止。这足够触发完整的Prefill计算（生成KV Cache），但不会浪费算力在Decode上。

2. **进程同步**：使用`multiprocessing.Event`确保Decode节点等待Prefill节点完成KV Cache传输后再开始。

3) **GPU隔离**：通过`CUDA_VISIBLE_DEVICES`环境变量将两个进程分配到不同的GPU上。

### 三、方案二：在线服务模式（1P1D部署）

vLLM官方提供了完整的在线服务脚本，支持1P1D（1个Prefill + 1个Decode）甚至XpYd（X个Prefill + Y个Decode）的部署。



#### 3.1 启动Prefill服务器

**start\_prefill.sh**：



```bash
#!/bin/bash
# Prefill服务器 - 运行在GPU 0，端口8100

export CUDA_VISIBLE_DEVICES=0
export MODEL=${MODEL:-"meta-llama/Meta-Llama-3.1-8B-Instruct"}

python3 -m vllm.entrypoints.openai.api_server \
    --model $MODEL \
    --port 8100 \
    --kv-transfer-config '{
        "kv_connector": "PyNcclConnector",
        "kv_role": "kv_producer",
        "kv_rank": 0,
        "kv_parallel_size": 2
    }' \
    --gpu-memory-utilization 0.8
```



#### 3.2 启动Decode服务器

**start\_decode.sh**：



```bash
#!/bin/bash
# Decode服务器 - 运行在GPU 1，端口8200

export CUDA_VISIBLE_DEVICES=1
export MODEL=${MODEL:-"meta-llama/Meta-Llama-3.1-8B-Instruct"}

python3 -m vllm.entrypoints.openai.api_server \
    --model $MODEL \
    --port 8200 \
    --kv-transfer-config '{
        "kv_connector": "PyNcclConnector",
        "kv_role": "kv_consumer",
        "kv_rank": 1,
        "kv_parallel_size": 2
    }' \
    --gpu-memory-utilization 0.8
```



#### 3.3 启动Router（路由层）

Router负责将请求路由到Prefill和Decode实例：



```bash
#!/bin/bash
# Router - 协调Prefill和Decode服务器

python3 -m vllm_router.app \
    --port 8005 \
    --service-discovery static \
    --static-backends "http://localhost:8100,http://localhost:8200" \
    --static-models "meta-llama/Llama-3.1-8B-Instruct,meta-llama/Llama-3.1-8B-Instruct" \
    --static-model-labels "llama-prefill,llama-decode" \
    --routing-logic disaggregated_prefill \
    --prefill-model-labels "llama-prefill" \
    --decode-model-labels "llama-decode" \
    --log-stats \
    --log-stats-interval 10
```



#### 3.4 发送推理请求

```bash
curl http://localhost:8005/v1/completions \
    -H "Content-Type: application/json" \
    -d '{
        "model": "meta-llama/Llama-3.1-8B-Instruct",
        "prompt": "What is the capital of France?",
        "max_tokens": 50,
        "temperature": 0
    }'
```



#### 3.5 一键部署脚本（XpYd架构）

vLLM官方提供了支持XpYd（多Prefill + 多Decode）的一键部署脚本：



```bash
#!/bin/bash
# 1P3D架构：1个Prefill + 3个Decode

export MODEL="meta-llama/Llama-3.1-8B-Instruct"
export PREFILL_GPUS="0"
export DECODE_GPUS="1,2,3"
export PREFILL_PORTS="20003"
export DECODE_PORTS="20005,20007,20009"
export PROXY_PORT="30001"

bash examples/online_serving/disaggregated_serving_p2p_nccl_xpyd/run.sh
```



该脚本支持灵活配置：



* `PREFILL_GPUS="0,1"` → 2个Prefill实例

* `DECODE_GPUS="2,3,4,5"` → 4个Decode实例

* 自动配置`kv_rank`和`kv_parallel_size`

### 四、进阶：LMCache + Mooncake部署

对于大规模生产环境，可以使用LMCache作为KV Cache的中转存储：



**Step 1: 安装LMCache**



```bash
pip install lmcache
```



**Step 2: 启动LMCache服务器**



```bash
# LMCache服务器默认端口8100
export LMCACHE_USE_EXPERIMENTAL="True"
export LMCACHE_CHUNK_SIZE="256"
python3 -m lmcache.server
```



**Step 3: 启动Prefill节点**



```python
# Prefill节点配置
ktc = KVTransferConfig.from_cli(
    '{"kv_connector":"LMCacheConnector","kv_role":"kv_producer",'
    '"kv_rank":0,"kv_parallel_size":2}'
)
```



**Step 4: 启动Decode节点**



```python
# Decode节点配置
ktc = KVTransferConfig.from_cli(
    '{"kv_connector":"LMCacheConnector","kv_role":"kv_consumer",'
    '"kv_rank":1,"kv_parallel_size":2}'
)
```



LMCache方案的优势在于：



* **KV缓存持久化**：即使P实例重启，KV Cache仍可复用

* **跨实例共享**：多个D实例可共享同一份KV Cache

* **支持卸载**：可将KV Cache卸载到CPU内存或磁盘

### 五、常见问题排查

| 问题                   | 可能原因         | 解决方案                                      |
| -------------------- | ------------ | ----------------------------------------- |
| `NCCL连接超时`           | 节点间网络不通      | 检查`kv_parallel_size`是否匹配                  |
| `CUDA out of memory` | 显存不足         | 降低`gpu_memory_utilization`到0.7            |
| `Prefill节点过早退出`      | 进程同步问题       | 使用`Event`等待或添加`while True: time.sleep(1)` |
| `Router无法发现后端`       | 服务发现配置错误     | 检查`--static-backends`端口是否正确               |
| `KV传输失败`             | Connector不兼容 | 尝试`PyNcclConnector`代替`P2pNcclConnector`   |





### 六、本代码与生产环境的差距

| 本教学演示    | 生产环境部署            | 差异说明                   |
| -------- | ----------------- | ---------------------- |
| 单机双卡     | 多机多卡集群            | 生产环境需RDMA/InfiniBand网络 |
| 手动启动进程   | Kubernetes + Helm | 生产环境需容器编排和自动扩缩容        |
| 静态服务发现   | 动态服务注册            | 生产环境需Consul/etcd等服务发现  |
| 基础NCCL传输 | Mooncake/NIXL优化   | 生产环境需专用KV传输优化          |
